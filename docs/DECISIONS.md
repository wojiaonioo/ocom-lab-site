## ADR-001 · 首屏用 Canvas 2D，不用 WebGL / Three.js

**日期** 2026-08-19　**状态** 生效

**背景**
参考 skill `shopify-editions-3d-site` 要求 sticky WebGL 场景、GLTF/DRACO/KTX2 资产管线。
但方案 v1.0 §08 明确写："只有在科学表达确有必要时才引入 WebGL"，
禁止项含"大面积 3D 海浪""为了动效而加载过大视频或高成本三维场景"，
技术建议为"首页粒子与简单流线可采用轻量 Canvas"。

**决策**
首屏海沟场景用 **Canvas 2D**。保留 skill 的**工程骨架**（sticky 场景层、序号侧栏、
主题感知导航、场景状态机、三层降级、canvas 非空验证），换掉其**技术选型与视觉**。

**理由**
1. 方案优先（CLAUDE.md 规定）。
2. 要画的东西——海沟纵剖面、等深线、粒子平流、深度轴——本质是 2D 科学图，
   用 3D 渲染反而要额外解决文字标注和坐标可读性。
3. skill 自己的质量红线是"No blank WebGL canvases"，Canvas 2D 从根上消除这个风险。
4. 无构建步骤、无 CDN 依赖，符合方案 §10"低 JavaScript 负担"与研究所静态服务器部署。

**代价**
放弃真实光照与 3D 地形透视。若后续确需（如深渊地形三维漫游），
按 ADR-002 的隔离方式接入，`science/` 不动。

**判据** REFERENCES-SWE 案例 5（渲染技术是可替换的细节）

## ADR-002 · `science/` 与 `content/` 定为 level 0 且互不依赖

**日期** 2026-08-19　**状态** 生效

**背景**
最容易写成一团的地方是"物理模型"和"渲染"混在 rAF 回调里，
以及"科研内容"和"DOM 模板"缝在一起。

**决策**
- `science/`：纯函数，**不 import 任何本项目目录**，不出现 DOM 全局。
- `content/`：纯数据 + 关联索引，同上。
- 二者互不引用。渲染层同时消费两者。

**理由**
1. 换渲染技术（ADR-001 的退路）时内核零改动。
2. `science/` 可被 Node 直接跑：单测、构建期批量生成论文视觉摘要。
3. `content/` 将来换成 Astro Content Collections / MDX 时（方案 §10），只换这一层的读取实现。
4. 命中方案原则 04"内容可维护"——科研人员改 `content/` 不会碰渲染代码。

**代价**
渲染层要自己做单位换算和坐标映射，不能图省事把画布尺寸塞进物理函数。

**判据** REFERENCES-SWE 案例 1（Parnas secret）、案例 2（Lakos levelization）、案例 3（VS Code 环境维度）

## ADR-003 · 不引入组件框架与状态库

**日期** 2026-08-19　**状态** 生效

**背景** 直觉上 React + Zustand 更"现代"。

**决策** 原生 ES Modules + 渐进增强。跨层通信用 `core/bus.js`（约 40 行）。

**理由**
1. 方案 §10 要求"低 JavaScript 负担"，§12 验收要求"核心内容在脚本失败时仍可阅读和导航"。
   框架 hydration 失败会整页白屏，与验收标准冲突。
2. 全站可变状态只有 6 项（语言 / 活动版块 / 导航主题 / 搜索 / 渲染质量 / reduced-motion）。
   为 6 个布尔和字符串上 store 是 Ousterhout 意义上的浅模块。
3. 方案 §10 的目标栈是 Astro（默认零 JS）。现在写成原生 ESM，迁 Astro 时几乎是平移。

**代价** 列表渲染要手写。用 `ui/` 里的小工具函数兜住，不做通用模板引擎。

**判据** REFERENCES-SWE 案例 4（浅模块应删）

## ADR-004 · 首屏叙事用"滚动下潜"，而非分屏轮播

**日期** 2026-08-19　**状态** 生效

**背景**
方案 §06 要求首页是"从表层下潜到深渊，再从观测证据上浮到科学解释"的叙事路径，
且 §06.1 明确"默认不自动切换成果"。

**决策**
`#stage` 为 200vh 的 sticky 舞台。滚动进度 `p ∈ [0,1]` 驱动**深度窗口**：
`p=0` 显示 0–11500 m 全水柱；`p=1` 收敛到 5500–11200 m 深渊段。
Hero 文案在 `p<0.35` 淡出，深渊读数面板在 `p>0.45` 淡入。
"发现标签"（三个专题）**由用户点击切换**，不自动播放。

**理由**
下潜是"深度尺度"的直接视觉表达，属于方案 §08 允许的"动效必须对应流动、传播、混合或观测过程"。
滚动是用户主动行为，不打断阅读；自动轮播会（方案原话）"造成访客阅读中断和移动端性能浪费"。

**代价**
200vh 舞台在移动端要压到 150vh 并简化粒子，否则滑动成本过高。

**判据** 方案 v1.0 §06.1 首屏交互约束

## ADR-005 · 占位内容必须可见标注，不编造人名与 DOI

**日期** 2026-08-19　**状态** 生效

**背景**
demo 需要看起来完整，但方案 §11/§12 要求人员信息、论文、联系方式、图片权限上线前逐项核验。

**决策**
1. 页面顶部常驻 demo 提示条。
2. 人员卡用角色占位（"研究员 · 学科带头人（待确认）"），**不编真实姓名**，头像用程序生成字母标记，不用照片。
3. 论文条目用方案已公开的研究主题改写为示例标题，DOI 字段一律显示"待补充"，**不生成假 DOI**。
4. 所有占位数据在 `content/` 中带 `placeholder: true` 字段，可一键筛出。

**理由** 学术站的可信度是唯一资产；假引用一旦被外部抓取即不可撤回。

**代价** demo 观感略逊于填满假数据的版本。用真实的科学图形（地形、剖面、流场）补足质感。

**判据** 方案 v1.0 §11 素材清单、§12.1 上线签署项

## ADR-006 · 地图用手绘简化岸线的 SVG，暂不接 MapLibre

**日期** 2026-08-19　**状态** 生效

**背景** 方案 §10 推荐 MapLibre GL 做航次地图。

**决策**
demo 阶段用 `figures/station-map.js` 输出 SVG 示意图，坐标经 `science/projection.js` 等距圆柱投影，
站位用真实经纬度，岸线为**粗略简化多边形**并在图上明示"示意图 · 简化岸线，非制图产品"。

**理由**
1. MapLibre 需要瓦片源（网络）与约 200 KB JS，与"首屏低 JS 负担"和离线演示冲突。
2. demo 要验证的是**信息架构**（站位 → 航次 → 数据 → 论文的关联跳转），不是底图精度。
3. 投影和站位数据放在 `science/` + `content/`，换 MapLibre 时只重写 `figures/station-map.js`。

**代价** 岸线不精确。已在图面标注，且 P3 阶段替换为 MapLibre + 真实底图。

**判据** REFERENCES-SWE 案例 5（底图是细节，站位关联是内核）
